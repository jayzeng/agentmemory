AgentMemory Production Readiness Review

Repository: jayzeng/agentmemory
Version reviewed: 0.4.13 at commit 46c4eb7
Review date: 2026-08-11
Scope: Evaluation dataset and methodology, runtime storage, security and privacy, qmd integration, CLI/public API, skills and installers, packaging, CI/CD, release supply chain, documentation, and operational maturity.

Bottom line: AgentMemory has a compelling low-dependency design and a substantial deterministic test suite, but it is not yet production-safe for sensitive or concurrent multi-agent workloads. The immediate blockers are a trust-filter bypass, memory-root escapes, qmd cross-profile isolation failure, and reproducible lost writes. The current evaluation suite is useful as a targeted regression harness, not as an independent quality benchmark.

Executive summary

Release blockers

  1. Trust and lifecycle metadata can be bypassed with a leading blank line, allowing explicitly untrusted or expired instructions into injected context.
  2. Daily reads can traverse outside the memory directory, and symlinked memory files can redirect reads/writes outside the root.
  3. qmd collection identity is not bound to the configured memory directory, so --dir can search another profile’s collection.
  4. Concurrent writers lose data. In a local 80-write / 24-worker probe, only 61 entries survived.
  5. Agent-facing direct search returns untrusted/expired qmd snippets without the safety filtering used by context injection.

Production posture

Area Assessment
Core design Strong simplicity and portability goals; excessive singleton state and synchronous whole-file I/O limit production embedding and scale.
Data integrity Not ready for concurrent agents; no locking, atomic replacement, backup, repair, or format migration.
Security/privacy Several root-boundary and trust-policy defects; default file permissions and global project scope are too permissive for sensitive memories.
qmd operations Useful optional integration, but profile binding, freshness, failure reporting, cold starts, and version observability need redesign.
Evaluation Good diagnostic/regression start; not an independent benchmark and currently emits a semantic false failure.
Delivery Linux/Node 20 focused despite cross-platform claims; release provenance, dependency automation, and governance are incomplete.
Documentation README is more accurate than the website and design document; several operational flags and destructive behaviors need stronger treatment.

Complete finding register

1. Security and privacy

SEC-01 — Trust/lifecycle filter bypass — Critical · Reproduced

isInactiveMemoryEntry() examines only the first paragraph (src/core.ts:171-179). A blank line immediately after a timestamp marker makes that marker the entire first paragraph, so following Trust: untrusted, Status: expired, or Valid until metadata is ignored and the body is injected.

Impact: Stored prompt injection or retired instructions can enter high-priority system context despite being explicitly labeled unsafe.
Remediation: Parse metadata from a strict entry envelope independent of blank lines; validate all timestamped writes; add adversarial whitespace/BOM/line-ending tests.

SEC-02 — Daily path traversal — Critical · Reproduced

dailyPath(date) blindly joins input (src/core.ts:104), while CLI and public reads accept arbitrary dates (src/cli.ts:239, src/core.ts:1716).

Impact: A crafted date can read any accessible .md file reachable by traversal, contradicting the skill claim that commands stay inside the memory directory.
Remediation: Require exact YYYY-MM-DD, resolve the final path, and enforce canonical containment beneath DAILY_DIR.

SEC-03 — Symlink root escape — High · Reproduced

Memory paths are followed with ordinary readFileSync/writeFileSync; there is no lstat, canonical containment check, or no-follow open. A symlinked MEMORY.md redirected a write outside the configured root.

Impact: Another local process, compromised workspace, or misconfiguration can redirect sensitive reads/writes.
Remediation: Canonicalize the root, reject symlink components for managed files, and use safe open/create semantics.

SEC-04 — qmd cross-profile disclosure — Critical · Reproduced

All stores use the singleton collection name agent-memory (src/core.ts:580). checkCollection() validates only the name (src/core.ts:785-811), not the configured path. Direct search then returns raw results (src/core.ts:1800-1858).

Impact: --dir or AGENT_MEMORY_DIR can search/update another profile’s index and expose unrelated project or personal memory.
Remediation: Derive collection identity from the canonical memory path, verify collection path on every open, and reject mismatches.

SEC-05 — Direct search bypasses trust/source policy — High · Reproduced

searchRelevantMemories() filters and source-verifies snippets, but CLI/public memorySearch() formats qmd results directly.

Impact: Agent-invoked search can reintroduce untrusted, expired, superseded, or externally indexed instructions that automatic context correctly rejects.
Remediation: Centralize one result-policy pipeline for context, CLI search, and public API search; optionally expose raw inspection only behind an explicit flag.

SEC-06 — No project/workspace isolation by default — High · Design risk

All projects share ~/.agent-memory; skills do not derive or pass a project-specific directory. README.md:16 describes project memory, but default behavior is global.

Impact: Facts, source paths, client names, and operational details from one repository can enter unrelated projects.
Remediation: Add explicit scopes (global/user/project), project IDs in entries, per-scope context policy, and migration tooling.

SEC-07 — Memory files are not private by default — High · Reproduced

ensureDirs() uses default mkdir modes (src/core.ts:68-71) and writes inherit umask. Common 0022 produced 0755 directories and 0644 files.

Impact: Other local users may read memory on shared workstations or build hosts.
Remediation: Default to 0700 directories and 0600 files, preserve stricter existing modes, and document an opt-out for intentionally shared stores.

SEC-08 — Skill install/uninstall has no ownership protection — High · Reproduced

Install blindly copies over SKILL.md (src/core.ts:1025-1026); uninstall blindly deletes it (src/core.ts:1073). Bash and PowerShell behave similarly.

Impact: User-customized or third-party skills can be destroyed.
Remediation: Store a manifest with version/hash/owner, refuse unknown files unless --force, back up modifications, and uninstall only files whose hash matches an installed version.

SEC-09 — External memory is trusted by default — High · Architecture risk

Source: provenance does not affect trust. Stored Markdown is inserted into system context as instruction-like text; only exact manual metadata can suppress it.

Impact: Imported transcripts, copied documentation, or poisoned qmd content can become agent instructions.
Remediation: Model trust as structured metadata, default imported/external content to untrusted, quote memories as data, and maintain source allow/deny policies.

SEC-10 — Secret screening is narrow and raw tools bypass legacy redaction — Medium · Code-confirmed

The scanner covers four regex families (src/core.ts:155-160). It misses many JWT, PEM/private-key, database URL, password, Slack/npm/Azure, bearer, and provider-specific formats. Raw read and direct search return legacy content unchanged.

Impact: Sensitive values can persist and be surfaced to agents.
Remediation: Add broader provider patterns, PEM/JWT/URL credential checks, optional entropy scanning, bounded redacted reads by default, and explicit raw-inspection controls.

2. Data integrity, durability, and scale

DATA-01 — Concurrent writes lose entries — Critical · Reproduced

Appends are read → concatenate → truncate-and-rewrite (src/core.ts:1414-1428, 1534-1536) with no inter-process lock or conflict detection.

Impact: The core multi-agent use case silently loses memory.
Remediation: Add cross-process locking and atomic temp-file replacement, or a safe append protocol with recovery tests.

DATA-02 — Writes are not crash-safe — High · Code-confirmed

writeFileSync truncates targets in place; there is no temp file, fsync, journal, checksum, or recovery copy.

Impact: Process/host failure or disk-full conditions can leave partial or empty high-value files.
Remediation: Write to a same-filesystem temp file, fsync, atomic rename, and retain a rotating backup.

DATA-03 — distil destructively replaces curated memory — High · Reproduced

Only an exact ## Pinned section is preserved (src/core.ts:2168-2174); MEMORY.md is overwritten at src/core.ts:2255.

Impact: Durable decisions not represented in daily/tag data disappear.
Remediation: Make preview the default, require --apply, back up the file, or generate a separate INDEX.md.

DATA-04 — No format version, migrations, integrity check, backup, or repair — High · Product gap

Production files contain no schema/version marker and there is no migration, verify, restore, retention, quota, or corruption-repair command.

Impact: Future parser changes and accidental corruption have no controlled recovery path.
Remediation: Define a versioned entry envelope, migration contract, verify, backup, restore, and retention/archive operations.

DATA-05 — Output budgets do not bound input work — High · Code-confirmed

Context reads entire files synchronously before truncation; topic context scans all topic files; distil reads all daily/topic history.

Impact: Large histories can block the process or exhaust memory even though final context is capped at 16K.
Remediation: Implement bounded tail/head readers, file-size limits, incremental indexes, pagination, and streaming distillation.

DATA-06 — Reads and search responses are unbounded — Medium · Code-confirmed

memoryRead and CLI read return complete files; direct qmd results have no response-byte cap.

Impact: A tool call can overflow an agent context, API response, terminal, or memory budget.
Remediation: Add default previews, offset/limit, maximum aggregate bytes, and explicit --raw/--all modes.

DATA-07 — Metadata fields permit structural injection — High · Reproduced

Only sourceUri is single-line sanitized (src/core.ts:230-241). sessionId, topic display name, and topic date can inject comment terminators, headings, lifecycle metadata, and arbitrary lines.

Impact: Entry boundaries, trust policy, provenance, and Markdown structure can be corrupted.
Remediation: Validate every metadata field, escape comment delimiters, enforce date/schema formats, and generate opaque entry IDs.

DATA-08 — Scratchpad multiline content is silently lost — Medium · Reproduced

Serialization permits newlines, but parsing recognizes only checklist-prefixed lines. Subsequent mutation rewrites only parsed items.

Impact: User TODO detail disappears without warning.
Remediation: Reject/escape newlines, support indented continuation lines, or store structured item blocks with IDs.

DATA-09 — Date and mode contracts drift — Medium · Reproduced

README advertises write --date and generic append/overwrite mode, but daily writes always use todayStr() (src/core.ts:1414) and daily/topic mode is silently append. Day and expiry calculations use UTC ISO semantics.

Impact: Backfills land on the wrong day; automation believes overwrite/date were honored; local-day boundaries surprise users.
Remediation: Define target-specific options, reject unsupported combinations, validate dates, and expose/document timezone behavior.

DATA-10 — Distil silently truncates taxonomy and misreports totals — Medium · Reproduced

Only 15 section tags and 20 index tags are emitted (src/core.ts:2164-2165); totalTags is indexTags.length (2267) rather than the true total.

Impact: Less-common knowledge disappears from the generated index and metrics are misleading.
Remediation: Report true totals, expose caps in output, paginate/index all tags, and emit truncation diagnostics.

DATA-11 — Entry identity and topic naming are weak — Medium · Design risk

Timestamp-to-second plus an eight-character session label is not guaranteed unique. Slug collisions merge distinct topic names; backlink dates can dangle.

Impact: Reliable supersession, deduplication, audit, and targeted editing are difficult.
Remediation: Assign immutable UUID/ULID entry IDs and store normalized topic metadata separately from display names.

3. qmd integration and operations

QMD-01 — CLI writes do not start background embedding — High · Reproduced

Embedding is scheduled after update on a five-second unref’ed timer (src/core.ts:850-861). A one-shot CLI exits before the timer fires.

Impact: Keyword index updates, but semantic/deep embeddings remain stale until explicit sync.
Remediation: Spawn detached embedding immediately after update, use a persistent worker, or mark semantic indexing manual and report staleness clearly.

QMD-02 — “Background” update blocks writes — Medium · Reproduced

Writes await qmd detection and the update timer/child remains referenced (src/core.ts:864-873).

Impact: Every one-shot write can take seconds; the README’s fire-and-forget claim is false.
Remediation: Queue work in a detached helper/daemon or make update explicitly synchronous with honest status and timing.

QMD-03 — Init/sync can report success on failure — High · Reproduced

runQmdUpdateNow() discards callback errors (src/core.ts:876-882); init sets indexUpdated=true unconditionally; sync returns exit code 0 when update/embed fail.

Impact: Automation and users believe search is healthy when it is stale or absent.
Remediation: Propagate typed errors, set non-zero exit codes, and include actionable stderr in JSON.

QMD-04 — Index failures are silent and have no retry queue — Medium · Code-confirmed

Scheduled update callbacks ignore errors; detached embedding has no durable status, backoff, or per-write pending marker.

Impact: Search silently diverges from Markdown source of truth.
Remediation: Persist dirty state, retry with bounded backoff, expose last successful sync/error, and make status authoritative.

QMD-05 — Cold semantic latency is operationally large — Medium · Reproduced

The isolated live eval’s first semantic query took 42.1 seconds; later queries took ~2.4 seconds.

Impact: CLI search can appear hung; 3-second prompt retrieval silently drops relevant memory on cold starts.
Remediation: Prewarm models, expose cold/warm telemetry, make timeouts configurable, and document measured latency distributions.

QMD-06 — qmd/model versions are unpinned and unreported — Medium · Reproducibility/supply-chain risk

Installation points to an unpinned Git repository; reports/status do not capture qmd version, model, index format, or corpus hash.

Impact: Behavior and eval results drift across installations; upgrades can break command parsing.
Remediation: Pin supported versions/releases, implement compatibility checks, and record version/model/index metadata.

QMD-07 — Postinstall can hang indefinitely — Medium · Code-confirmed

scripts/postinstall.cjs runs synchronous qmd status without a timeout.

Impact: A broken qmd executable can block npm install.
Remediation: Add a short timeout, make detection opt-in or non-blocking, and never make optional tooling part of install critical path.

QMD-08 — Operational configuration is incomplete — Low · Docs gap

AGENT_MEMORY_QMD_EMBED exists but is undocumented; sync, distil, and status --probe are absent from the README command table.

Remediation: Publish a complete config/command reference with update/embed lifecycle diagrams and failure semantics.

QMD-09 — Multi-process indexing is uncoordinated — Medium · Architecture risk

Each CLI process can detect, update, and attempt embedding independently; there is no shared lock or coalescing daemon.

Impact: Concurrent agents create redundant expensive work and may contend on qmd’s index.
Remediation: Single-flight updates per collection, process lock, and observable queue state.

4. CLI, public API, cross-platform, and agent integration

API-01 — Runtime enums are not validated — High · Reproduced

In JavaScript, invalid write/read targets fall through to long-term behavior; invalid scratchpad actions return ordinary non-error results.

Impact: Bad integrations mutate/read the wrong file without detection.
Remediation: Validate every public API input at runtime and use a discriminated error/result contract.

API-02 — Search limit accepts invalid and extreme values — Medium · Reproduced

Number.parseInt is unchecked (src/cli.ts:391); NaN, zero, negative, and huge limits are passed to qmd.

Impact: Unclear failures or resource-heavy queries.
Remediation: Require an integer within a documented bound, e.g. 1–100.

API-03 — Windows default home handling is inconsistent — Medium · Code-confirmed

Core default uses HOME ?? "~" (src/core.ts:17), while installer code correctly falls back to USERPROFILE.

Impact: Windows users without HOME can write under a literal ~ path.
Remediation: Use os.homedir() consistently and test Windows path behavior.

API-04 — Multilingual storage conventions are ASCII-only — Medium · Reproduced

Japanese/Chinese topic names slugify to empty (src/core.ts:112-120); non-ASCII hashtags are ignored (1882-1887).

Impact: Multilingual users can retrieve content semantically but cannot organize it naturally.
Remediation: Unicode-aware normalization/slugs/tags with collision-safe IDs.

API-05 — Library is a mutable singleton — High · Architecture risk

Memory paths, qmd flags, timers, collection, home paths, and child-process adapters are module globals.

Impact: Multiple stores or tenants cannot be used safely in one process; concurrent tests/integrations interfere.
Remediation: Introduce an instance-based MemoryStore with immutable configuration and injected adapters.

API-06 — Synchronous I/O blocks embedding hosts — Medium · Architecture risk

Core uses synchronous file APIs throughout while being published as a reusable library.

Impact: Large stores block agent/server event loops.
Remediation: Provide async production APIs; keep sync wrappers only for the CLI if desired.

API-07 — Real agent provenance is not captured — High · Product gap

CLI hardcodes sessionId:"cli" (src/cli.ts:197); bundled skill write examples never include --source-uri.

Impact: Users cannot determine whether Claude, Codex, Cursor, or another session authored a memory. The provenance eval tests a fixture path, not real installed behavior.
Remediation: Pass agent/session/run IDs automatically and support structured source records.

API-08 — Large/multiline input relies on command arguments — Medium · Usability/security risk

There is no stdin/file input mode. Content appears in shell history/process listings and is constrained by OS argument limits.

Remediation: Add --content-file, --stdin, and JSON request modes; discourage sensitive content in argv.

API-09 — Agent lifecycle is instruction-based, not guaranteed — Medium · Product-contract gap

Except for Claude’s inline directive, skills ask agents to run context/search/write commands. Hosts do not guarantee execution, session-end logging, or prompt-aware retrieval.

Impact: Behavior varies by model/host and can silently disappear.
Remediation: Offer native hooks where available, expose capability levels per host, and avoid universal automation claims.

API-10 — Public package surface includes test internals — Low · API hygiene

Generated declarations export _setBaseDir, process overrides, qmd flags, timers, and other test hooks. The tarball also ships full src/ in addition to dist/.

Impact: Consumers couple to unstable internals and semver obligations grow.
Remediation: Curate package exports, move test hooks behind a test-only subpath, and ship only necessary source artifacts.

API-11 — CLI parser is intentionally minimal but under-validates — Low · Usability

Unknown flags are ignored; --key=value, -- termination, short flags, and values beginning with -- are unsupported.

Remediation: Reject unknown flags and either document the grammar precisely or adopt a small mature parser.

5. Evaluation dataset and methodology

EVAL-01 — Exact-marker oracle creates a semantic false failure — High · Reproduced

README says AgentMemory “is not a Python SDK, vector database, or knowledge graph” (README.md:26). The probe requires exact “does not provide …” strings (external-feedback-v1.json:397+) and reports product-identity as confirmed.

Remediation: Use normalized concepts, accepted regex alternatives, or a structured documentation contract rather than exact marketing copy.

EVAL-02 — Dataset validation permits vacuous cases — High · Reproduced

stringArray() accepts [] (eval/dataset.ts:7); fixture bodies and evaluator-specific contracts are mostly unvalidated; empty oracles can pass.

Remediation: Adopt JSON Schema/Zod-style complete runtime validation and require at least one meaningful assertion per executable probe.

EVAL-03 — Strict mode cannot distinguish regression from known gap — High · Reproduced

--strict fails on any failed probe (eval/run.ts:415). The shipped transcript-import product opportunity is intentionally expected to fail.

Remediation: Add expected status/baseline, regression-gate flags, and separate “known issue reproduced” from “unexpected regression.”

EVAL-04 — Evaluators are partly hard-coded or mislabeled — Medium · Code-confirmed

Prompt routing executes a baked scenario (eval/run.ts:95+); cross-agent is ordinary context construction (202); docs boundary always reads README.

Impact: Dataset fields do not fully drive execution, and “Claude-to-Codex” is not an actual two-agent integration.
Remediation: Make evaluators declarative and rename smoke proxies honestly.

EVAL-05 — This is a regression/diagnostic suite, not an independent benchmark — Medium · Methodology

Dataset, fixes, and probes landed together in commit ac678f6; there is no holdout, blinded labeling, or independent scorer.

Remediation: Separate development fixtures from a frozen external holdout and report both.

EVAL-06 — External-feedback provenance is not auditable enough — Medium · Methodology

Sources have URLs/titles but no author, publication/access dates, archived snapshot, exact excerpt, or per-claim quote. One of four sources is the repository’s own review.

Remediation: Store source snapshots/excerpts and trace each issue to exact evidence.

EVAL-07 — Multilingual corpus has very low external validity — Medium · Methodology

Five synthetic documents, four probes, one query per condition, top-1 substring checks, and minimal distractors cannot establish broad multilingual quality.

Remediation: Add many paraphrases/languages, lexical and semantic positive controls, hard negatives, distractor scaling, and real anonymized corpora where permitted.

EVAL-08 — Reports omit retrieval science and environment metadata — Medium · Methodology

No qmd/model/version, platform, corpus hash, score/margin, MRR/nDCG/recall, seed, repeated trials, or latency thresholds are recorded.

Remediation: Emit a reproducibility manifest and standard ranking/latency metrics with confidence intervals.

EVAL-09 — Issue verdict aggregation is simplistic — Medium · Methodology

Any failure becomes confirmed, all passes become not-reproduced, and a mixture becomes mixed (eval/run.ts:341-360), regardless of expected outcomes, severity, or probe applicability.

Remediation: Model claims, requirements, weights, expected outcomes, and evidence strength explicitly.

EVAL-10 — Eval is not a real CI product gate — High · Delivery gap

CI omits test:eval; publish runs unit-only npm test. Even test:eval primarily verifies harness execution and intentionally accepts product probe failures.

Remediation: Run harness validation in CI, maintain an expected baseline, fail only on regressions, and schedule isolated live-qmd compatibility jobs.

6. CI/CD, packaging, installers, docs, and governance

OPS-01 — Cross-platform/runtime claims exceed CI coverage — High

CI runs only Ubuntu with Node 20 and mutable Bun latest. There is no Windows/macOS or Node 22/24 matrix.

Remediation: Add OS/runtime matrices and platform-specific installer/path tests.

OPS-02 — qmd integration is not continuously tested — Medium

There is no pinned real-qmd CI lane. Local “qmd-free” suites can accidentally call the user’s real global qmd because update mode is not forced off.

Remediation: Force qmd off in unit tests, use shims for deterministic integration, and add a scheduled pinned real-qmd job.

OPS-03 — Critical failure modes lack tests — Medium

No committed tests cover traversal, locking/concurrency, symlinks, permissions, disk failures, large inputs, pagination, backups, malformed metadata, collection path mismatch, skill ownership, or Windows behavior.

Remediation: Convert every reproduced issue in this report into a regression test; add coverage and mutation/fault-injection targets.

OPS-04 — npm publication lacks modern provenance — High

Publish uses a long-lived NPM_TOKEN and plain npm publish (publish-npm.yml:16,48) without trusted publishing or provenance attestations.

Remediation: Use npm OIDC trusted publishing, --provenance, protected release environments, and immutable build inputs.

OPS-05 — Build dependencies/actions are mutable — Medium

GitHub Actions use major tags; Bun is latest; qmd is installed from an unpinned Git URL.

Remediation: Pin actions by commit SHA, pin Bun, and define a tested qmd version range/release checksum.

OPS-06 — Homebrew update workflow trusts unvalidated manual input — High · Code-confirmed

${{ inputs.tag }} is interpolated into shell/Python/branch fields (update-homebrew-formula.yml:31+) without strict semver validation; curl -L lacks --fail (:48).

Impact: Authorized dispatch input can break command/script structure or update the formula with a hashed error page.
Remediation: Pass values through environment variables, validate ^v\d+\.\d+\.\d+$, use curl --fail --show-error, and verify archive/package version.

OPS-07 — Installed skills have no version/upgrade manifest — Medium

There is no recorded package version, source hash, install timestamp, or modified-state detection.

Impact: Skills become stale after package upgrades and cannot be safely updated/uninstalled.
Remediation: Add a manifest and install-skills --check/--upgrade/--force lifecycle.

OPS-08 — Installer implementations drift — Low

PowerShell has no uninstall mode; Bash uses unnecessary eval; core, Bash, and PowerShell duplicate detection/ownership logic.

Remediation: Drive all installers from one manifest/implementation and test parity on each OS.

OPS-09 — Website and design docs overclaim/stale — Medium

Website says qmd surfaces memory into “every turn, automatically” (docs/index.html:471-472,515,557), while README correctly says session-start context plus explicit search (README.md:173). design.md has obsolete line counts, test counts, injection behavior, and “no entry boundary tracking.” Historical README copy at :297 repeats old automatic behavior.

Remediation: Establish one capability matrix/source of truth and test important claims as documentation contracts.

OPS-10 — Main CLI/config reference is incomplete — Low

README table omits version, distil, and sync; config omits embed mode; status --probe and destructive distil safety deserve stronger documentation.

OPS-11 — Security and maintenance governance is absent — Medium

No SECURITY.md, supported-version policy, private disclosure channel, CODEOWNERS, dependency bot, contribution guide, or issue templates.

Impact: Sensitive-memory vulnerabilities and dependency updates lack an operational process.
Remediation: Add disclosure/response SLAs, ownership, automation, and support policy.

OPS-12 — Dependency/runtime alignment needs maintenance — Low

One low-severity dev-only esbuild advisory arrives through apparently unused tsx; Biome/tsx/types are behind wanted versions; @types/node targets 25 while runtime floor is 20; npm and Bun lockfiles require manual parity.

Remediation: Remove unused dependencies, align Node types with supported runtimes, automate updates, and verify lockfile consistency.

OPS-13 — Local and release gates are incomplete/inconsistent — Medium

Tracked pre-commit runs unit-only npm test plus lint, while repository instructions require unit, CLI, lint, and build. Publish likewise omits CLI/eval tests.

Remediation: Define one verify script used by hooks, CI, and release; add eval-baseline and package smoke checks.

OPS-14 — Homebrew test is weak and environment-sensitive — Low

Formula test runs only status, which creates directories and may inspect a real qmd environment; it does not validate isolated write/read behavior.

Remediation: Set a temporary AGENT_MEMORY_DIR, disable qmd, and test version plus write/read round trip.

Strengths worth preserving

  • Zero production npm dependencies in the core path.
  • Plain Markdown remains inspectable, portable, and manually recoverable.
  • Strict TypeScript and substantial deterministic unit/CLI coverage.
  • Production child-process calls use argv arrays rather than shell interpolation.
  • Context output has a complete 16K cap and section priorities are explicit.
  • Automatic context search applies conservative source-root verification.
  • Secret screening, lifecycle filtering, and provenance show the right security direction even though the boundary needs hardening.
  • Tests generally use temporary memory directories; npm package portability has an end-to-end pack/install smoke test.
  • Live multilingual qmd smoke probes passed in the reviewed environment.

Recommended remediation plan

Phase 0 — Security and data-loss release blockers

  1. Replace lifecycle parsing with a strict, whitespace-insensitive, versioned entry envelope.
  2. Enforce canonical root containment for every read/write and reject symlinks.
  3. Bind qmd collection identity to canonical memory directory and filter all search surfaces.
  4. Implement cross-process locking plus atomic durable writes.
  5. Add regression tests for the exact reproduced exploits and races.

Phase 1 — Durability and privacy

  1. Restrict filesystem permissions.
  2. Add backup/restore/verify and make distil non-destructive by default.
  3. Add project/global scopes and structured trust/provenance.
  4. Bound reads, search outputs, file sizes, and history processing.
  5. Introduce stable entry IDs and runtime schemas.

Phase 2 — qmd and API reliability

  1. Replace singleton globals with instance-based store configuration.
  2. Redesign update/embed as an observable single-flight worker or explicit sync model.
  3. Propagate errors and non-zero exit codes; add retry/dirty state.
  4. Pin and report qmd/model/index versions.
  5. Add async/paginated APIs, stdin/file inputs, Unicode-safe topics/tags, and full runtime validation.

Phase 3 — Evaluation credibility

  1. Fix the semantic false failure and add expected outcomes/baselines.
  2. Fully validate the dataset schema and make evaluators declarative.
  3. Capture source excerpts/snapshots and split development from holdout data.
  4. Expand multilingual/ranking/latency methodology and emit reproducibility manifests.
  5. Add baseline eval and scheduled pinned live-qmd jobs to CI.

Phase 4 — Delivery and operational maturity

  1. Add Windows/macOS and Node LTS matrices.
  2. Adopt npm trusted publishing/provenance and SHA-pinned actions.

Review limitations

This was a static and targeted dynamic review, not a formal penetration test. Linux/macOS behavior was exercised locally; Windows behavior was inspected but not executed. Live qmd evaluation used the installed qmd environment and an isolated corpus, but the current harness does not record qmd/model versions. Findings labeled Reproduced have direct probe evidence; Code-confirmed findings follow deterministically from implementation; Design risk/Product gap findings require product-policy decisions but are material to production readiness.
